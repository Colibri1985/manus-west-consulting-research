# Инструкция: автономный конструктор БДДС

## Запуск

1. Скачайте [bdds-constructor.html](./bdds-constructor.html).
2. Откройте файл двойным щелчком в современном браузере.
3. Интернет, сервер и установка библиотек не требуются.

Данные не отправляются наружу. Автосохранение в браузере используется как дополнительное удобство; основной файл бюджета — JSON.

## Рабочий сценарий

1. В шапке укажите проект, период, единицы отображения и при необходимости начальный остаток.
2. На вкладке **Справочники** проверьте статьи из `ШаблонБДДС.xlsx`. Группы не предназначены для прямого ввода.
3. На вкладке **Доходы** добавляйте доходы. Для эксплуатации можно задать базу и тариф: начисление рассчитывается как `тариф × база`.
4. Для дополнительных услуг выберите режим отдельно для каждой позиции:
   - «Не создавать расход»;
   - «Расход абсолютной суммой»;
   - «Наценка на расход» по формуле `доход / (1 + p / 100)`.

   Пустой процент оставляет позицию черновиком и не включает её в итог. Явный `0%` допустим.
5. На вкладке **Работы и платежи** добавляйте подрядные работы, услуги и материалы. Описание материала хранится отдельно и не влияет на расчёт. График закупки задаётся независимо.
6. На вкладке **Персонал** задайте обезличенные строки мини-ШР. Налоговые параметры намеренно не подставляются: налоговый профиль требует подтверждения.
7. На вкладке **Реестр** проверяйте исходные позиции и рассчитанные денежные события.
8. На вкладке **БДДС и экспорт** проверяйте матрицу по датам денег.
9. Нажмите **Проверить**, затем **Сохранить**. JSON можно открыть повторно кнопкой **Открыть**.

## Выгрузки

- **Рабочий JSON** — кнопка «Сохранить».
- **Проверочный XLSX** — содержит листы БДДС, Позиции, Платежи, Персонал, Замечания.
- **Сметная детализация** — CSV с отдельной строкой на позицию и описанием материала.
- **Адаптер БИТ** — намеренно не создаёт производственный файл и сообщает: «Требуется подтверждённый формат загрузки БИТ».

## Демонстрация

Кнопка **Демо-данные** загружает условный бюджет с эксплуатационным доходом, тестом `120 ₽ / (1 + 20 / 100) = 100 ₽`, ежемесячным ТО, материалом и строкой мини-ШР. Эти значения не используются как значения по умолчанию для новых записей.

## Правило знаков

В БДДС поступления показываются положительными, выплаты — отрицательными. Готовые группы и итоговые показатели строятся из рассчитанных денежных событий. Черновики показываются в реестре, но не включаются молча в окончательный итог.

## Безопасность данных

Импорт сначала проверяет обязательную структуру JSON. При ошибке текущий бюджет не заменяется. Пользовательские строки выводятся как текст, а формульные значения при CSV-выгрузке экранируются апострофом.
