## 6. Предложение следующего согласуемого изменения — ещё НЕ применено

Объект: config.yaml текущего профиля, общий для gateway/dashboard. Добавление наборов относится к Telegram этого профиля, а не только к теме настройки.

Предлагаются ровно следующие целевые поля:

```yaml
platform_toolsets:
  telegram:
    - clarify
    - debugging
    - no_mcp
    - cronjob
    - memory
    - session_search
    - skills
memory:
  write_approval: true
skills:
  write_approval: true
```

Это фрагмент целевых значений, НЕ инструкция перезаписать весь YAML или существующие разделы. Все остальные значения должны сохраняться. В частности, не включаются delegation, kanban или MCP; не ослабляются approvals.mode/cron_mode, не меняются модель, права, память или клиентские документы.

Причина flags write_approval: появление инструмента памяти/skills не должно неявно превращаться в разрешение на автономное накопление записей и изменение процедур. Фактическое соблюдение этих flags нужно подтвердить отдельно; сами flags не доказывают запрет обхода через иные инструменты.

Перед применением необходимы: подтверждение этого объёма, резервная копия, проверка требований установленного кода, проверка отсутствия активной работы и согласованный способ обновления интерфейсов. При необходимости перезапуска нужно назвать конкретные сервисы и последствия; рабочие темы не сбрасываются через /new.

После применения и readback: сначала безопасные операции чтения, затем отдельно обозначенные тестовые записи без клиентских данных и контроль согласования. Никакого утверждения о полной исправности по одному удачному вызову.
