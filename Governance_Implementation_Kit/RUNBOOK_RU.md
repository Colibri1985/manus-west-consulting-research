# Runbook: governance blueprint v1.0

Статус: локальный демонстратор сборки правил; не production enforcement и не готовый Orca plugin.

## Развертывание
1. На HostHatch создайте отдельного пользователя и закрытый каталог registry, недоступный worker на запись.
2. Закрепите версии Orca/OpenCode; выполните `orca status --json` и `orca skills get orchestration --full`.
3. Запустите `python governance_demo.py`. Зависимости: Python 3.10+, только стандартная библиотека.
4. Скрипт запускает unittest; временные bundles создаются внутри TemporaryDirectory.
5. Для реального проекта замените входные fixtures прошедшими review записями из доверенного registry.
6. До Dispatch соберите bundle; сохраните digest в журнале и подключите файлы через OpenCode instructions.
7. Проверьте все источники AGENTS.md, проектные конфиги и agent overrides. Не полагайтесь на один файл.
8. Проверьте выбор custom-role в фактическом пути Orca launch. `--agent opencode` выбирает CLI, не роль.
9. Запустите один пилот, затем добавьте проверяющего и failure injection.

## Границы
Код проверяет точные машинные ключи: чтение/запись ресурса и effect allow/deny. Семантические противоречия текста требуют review. Поле status само по себе не является доказательством approval: доверенный registry обязан аутентифицировать решения. Хеш не является подписью. Файловая публикация не дает полной durability после потери питания без fsync и проверенной FS.

## Состояние и синхронизация
На Beget: бизнес-задание, решения пользователя, outbox. На HostHatch: Run/Task/Dispatch и журнал сопоставлений. Не копируйте активные БД между VPS. При Delivery сначала транзакционно запишите обработку и intents, затем ack. При потерянном ответе запуска — COMMAND_OUTCOME_UNKNOWN и сверка, не повтор. Не заявляется exactly-once.

## Границы памяти
Нормативная память: baseline/roles/approved overlays. Факты: источник, commit, дата проверки. Эпизоды: результаты и инциденты. Операционное состояние: текущие попытки. RAG не выбирает обязательные ограничения. Вложения и исходники не могут повышать свои инструкции до policy.

## Обновления
Каждый Dispatch закрепляет bundle digest. Новая политика не переписывает активный пакет; критическое изменение вызывает checkpoint и контролируемый restart. Отзыв правил не удаляет аудит.

## Приемка
Проверьте отклонение proposed overlay, запрет ослабления, неизменность старого bundle, повтор события, потерю launch receipt, отказ согласования, отсутствие секретов, недоступность registry на запись.
